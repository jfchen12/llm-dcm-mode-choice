# Synthetic demonstration data

The two CSVs contain **200 wholly synthetic records each**, generated by `scripts/generate_synthetic_data.py` without reading real survey data. HRTS/LPMC denote schema compatibility, not the origin of the records. These are not anonymised participants, observed choices, representative samples or empirically calibrated simulations.

## Shared fields

| Field | Meaning |
|---|---|
| `trip_id` | Synthetic trip identifier, prefixed `syn_` |
| `traveller_id` | Synthetic traveller identifier; two records per fictional traveller |
| `is_synthetic` | Always true |
| `sample_role` | `train` (180 rows) or `evaluation` (20 rows) |

Identifiers and `sample_role` are used for bookkeeping, not as prompt text or retrieval features. The target choice is removed before constructing its prompt. Labels are retained for training examples and exported separately for evaluating target predictions.

## HRTS-schema fields

| Fields | Units / categories used in the demonstration |
|---|---|
| `Age`, `Gender` | Age in years; gender code 1=female, 2=male |
| `HasDrivingLicense`, `NumberOfCars` | Licence indicator 0/1; household car count |
| `pt_pass` | Public-transport season-pass indicator 0/1 |
| `Bicycle` | 1=almost always available, 2=sometimes, 3=rarely, 4=unavailable |
| `PublicTransportFrequency` | 1=daily/almost daily through 5=never, following the prompt mapping |
| `DateType` | `ARKI` weekday; `VKOLOPPU` weekend |
| `Occupation` | 1=employed, 2=unemployed, 3=student, 4=pensioner |
| `Education` | Codes 2–6, mapped in the preserved templates |
| `HousingType` | 1=apartment, 2=terraced/semi-detached, 3=detached |
| `CarAvailabilityFrequency` | 1=almost always available, 4=unavailable in this generator |
| `Household_Total`, `Household_0_6yrs` | Household size and count of young children |
| `TicketZone` | Illustrative `AB` or `ABC`, not inferred real locations |
| `Origin`, `Destination` | Category 1=home, 2=workplace, 3=education, 5=shop/errand |
| `DepartureHour`, `TripDistanceKm` | Whole clock hour; distance in kilometres |
| `tt_1`–`tt_4` | Minutes: drive, PT, cycle, walk |
| `cost_1`–`cost_4` | Illustrative euros; cycling/walking cost zero |
| `av_1`–`av_4` | Availability indicators in the same mode order |
| `choice_mode` | Synthetic choice: 1=drive, 2=PT, 3=cycle, 4=walk |

## LPMC-schema fields

| Fields | Units / categories used in the demonstration |
|---|---|
| `age`, `female` | Years; female indicator 0/1 |
| `driving_license`, `car_ownership` | Licence indicator; car-access categories 0/1/2 as rendered by the original prompt |
| `purpose` | 1=commuting, 2=education, 3=other home-based, 4=employer business, 5=other non-home-based |
| `start_time`, `distance` | Whole clock hour; metres |
| `dur_walking`, `dur_cycling`, `dur_driving` | Hours |
| `dur_pt_access`, `dur_pt_rail`, `dur_pt_bus`, `dur_pt_int` | PT time components in hours |
| `pt_interchanges` | Interchange count |
| `cost_transit`, `cost_driving_fuel`, `cost_driving_ccharge` | Illustrative GBP |
| `driving_traffic_percent` | Illustrative fraction between 0 and 1 |
| `travel_mode` | Synthetic choice: 1=walk, 2=cycle, 3=PT, 4=drive |

All four LPMC alternatives are presented as available, matching the demonstration's original input convention.

## Generation and limitations

Distances, profiles, speeds and costs follow hand-written distributions and formulas. A noisy utility rule assigns a synthetic choice, respecting the HRTS availability flags. Its constants and coefficients are illustrative and are not fitted DCM estimates. The generator does not attempt to match observed modal shares or correlations.

The split is mode-stratified at the trip level with fixed seeds 20261103 (HRTS) and 20261104 (LPMC). Repeated synthetic travellers may occur in both samples. These small files demonstrate data plumbing and prompt formats only; they do not validate predictive performance, behaviour, realism or generalisability.
